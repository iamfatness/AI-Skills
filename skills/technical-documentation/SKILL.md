# Technical Documentation

## Inputs

Audience, task, source code or authoritative references, and output location.

## Workflow

1. Identify what the reader must accomplish and what they already know. Inspect actual interfaces and existing documentation.
2. Lead with a working path, prerequisites, and expected result. Explain choices and limitations at the point they matter.
3. Check commands, paths, links, version assumptions, and recovery guidance. Do not include secrets or claim an unexecuted command was tested.
4. Update affected references without rewriting unrelated content. Keep one authoritative home for each maintained fact.

## Output

Task-oriented documentation, checked examples, and any unverified instructions.

## Example

Document installation on Windows and Linux with conflict recovery and removal steps.
